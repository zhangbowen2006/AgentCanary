# 三分钟展示脚本

从 README 启动本地实验室，或打开公开 Demo。所有内容是合成记录，不调用真实模型、文件删除或网络工具。

**0:00–0:30 问题。** AI 助手读取客户资料后做了一次摘要，再把摘要发出去。如果安全检查只看 net.post 的参数，就容易失去资料来自哪里的证据。AgentCanary 将记录变成可重复的策略测试，而不是再用一个模型猜测风险。

**0:30–1:10 数据流。** 初始状态显示 9 次工具调用、3 次拒绝。选中 external-upload，右侧显示 personal 标签与 read-private 来源。摘要没有清除敏感性。再选择 publish-public：它只依赖公开文档，正常放行。这解释了为什么不能简单把“读过私人文件”之后所有操作都封掉。

**1:10–1:45 审批与预算。** 选择 delete-approved / reuse-approval：第一次精确绑定的审批有效，第二次复用被拒绝。选择 model-second：两次成本 600 + 500 = 1100，超过 1000。把预算改为 2000，拒绝数量从 3 变为 2；数据外发和审批规则继续生效。

**1:45–2:20 策略变更。** 恢复预算 1000，点击“对比基线策略”。基线只有审批约束，候选新增两次拒绝。关闭敏感数据约束时，界面立即展示变化。强调：这是同一条已观察历史的调用级比较，不能预测被拦截后模型会如何改走其他路径。

**2:20–2:45 工程价值。** 导出不含资源路径的结构化报告。展示 `node bin/agentcanary.mjs test examples/regressions.json`：敏感资料摘要外发必须拒绝，公开文档必须放行；任何调用缺少断言都会失败。策略从一个配置文件变成可以在 CI 中验证的行为契约。

**2:45–3:00 复用和边界。** 核心是可安装 Mooncakes 包，不依赖模型或云服务；CLI 和网页使用同一套 MoonBit 引擎。信任边界在采集器：它必须认证审批、完整记录依赖和标签。当前数据为合成样例，没有声称已有生产检出率。

## 评审常见问题

- **与 stateless allowlist 有何不同？** 维护 artifact 来源、单次审批生命周期和跨调用窗口，能解释跨步骤违规；deny/allow 本身也可组合。
- **与任务图 / Agent 框架有何不同？** 不执行 Agent 或任务图，不绑定模型提供商，输出的是策略判定、差异和可重复断言。
- **为什么用 MoonBit？** 状态与错误边界由类型约束，核心可在四个后端复用，同一代码连接命令行、浏览器和 Wasm 宿主。
- **为什么拒绝的调用还计费？** 因为输入记录的是已经发生的事实；离线改策略不能撤销实际发生的费用和数据流。
- **摘要是否应该去敏感？** 本版本不会做此推断。只有宿主可信的独立脱敏流程才能建立新的安全边界；模型声称“已脱敏”不能自动清掉标签。
- **审批是否防伪？** 不防伪；认证属于可信宿主。引擎严格检查绑定、时间、使用次数和撤销。
- **并发如何处理？** 每会话 seq 建立观察顺序；会话之间独立。不声称提供运行中并发事务门禁。
- **规模是否靠代码行数？** 不。公开统计、合成基准和具体测试证据，优先做完整可复现的边界。
- **后续最有价值的工作？** 接入一个真实 MoonBit Agent 的受信事件采集器，收集可授权公开的实际用例，验证遗漏依赖和标签的处理流程。
